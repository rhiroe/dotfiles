# Context efficiency
- 調査系は探索範囲を先に絞る。広い調査はサブエージェントに委譲し、要約だけ返す
- Bashで生のcat/find/grepを叩くより、組み込みのGrep/Glob/Readツールを使う
- ファイル全体のReadより先にgrep/globで該当箇所を特定し、必要な範囲だけ読む
- コマンド出力が大きい時は `| head -50` などで切り詰めてから読む
- テストは全体スイートではなく該当テストのみ実行する
- 変更後の確認は、ファイル全体の再読み込みではなく差分で行う

# Output
- 完了報告は要点のみ。変更したコードを本文に再掲しない
- 説明を求められていない限り、実装後の長い解説を書かない

# Compaction
- 要約時は、変更済みファイル一覧とテスト実行コマンドを必ず保持する

# Source comments
- 既定は「書かない」。書いて良いのはコードを読んでも分からない外部情報のみ（既知の不具合/仕様への参照、隠れた invariant、仕様の罠）
- 以下に該当するコメントは書かない/消す: コミットメッセージ相当の背景説明、意図の retrospect、コードの自然言語への翻訳、workaround の justify、移行中の状態説明
- 実装意図が分かりづらい箇所は、素直な書き方をしない理由を因果で一言書く。書く前にまず命名/分割でコメント不要にできないか検討する
